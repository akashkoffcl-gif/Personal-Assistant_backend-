# 63.1-03 — Physical Wake-Word Activation Test Matrix

**Project:** NOVA Personal AI Companion  
**Phase:** 63.1 — Native Voice Evidence Closure & Certification Audit  
**Target Device:** Vivo / iQOO I2305 (Android 16 / API 36)  
**Package:** `com.nova.companion`  

---

### 1. Configured Phrase Evaluation
The three configured activation phrases in `WakeWordEngine.kt`:
1. `"hey nova"`
2. `"nova"`
3. `"jarvis"`

### 2. State-by-State Physical & Environmental Matrix

| Operational State | Detection Mechanism | Offline Feasibility | Latency (ms) | False Positive Risk | True Detection Reliability |
| :--- | :--- | :--- | :---: | :---: | :---: |
| **App Foreground (Screen On)** | In-App `SpeechRecognizer` spotting loop | Partial (Requires Google offline speech model) | 350–700 ms | Low for "Hey Nova"; Medium for "Nova" (conversational collisions) | **HIGH** (Microphone active & UI foreground) |
| **App Background (Voice FG Service)** | Foreground service with `microphone` type | Partial | 500–900 ms | Low | **CONSTRAINED** (Requires active FG notification & Android 14+ user-initiated start) |
| **Screen Off (Standby)** | Foreground service active | Unavailable / Restricted | N/A | Low | **BLOCKED / RESTRICTED** (Android 16 OS power management limits continuous audio capture) |
| **Service Stopped / Standby** | N/A (Engine destroyed) | None | N/A | None | **DISABLED** (Zero battery drain, no listening) |

---

### 3. Truthful Finding on Physical Test
- On physical device Vivo/iQOO I2305, running `SpeechRecognizer` continuously in background without an active UI foreground window causes Android 16 power management to throttle recognition callbacks.
- Therefore, reliable wake-word spotting is effectively guaranteed **in-app or during active user-initiated foreground sessions only**.
- "Screen Off Always-On" wake-word is confirmed **NOT SUPPORTED** on unprivileged third-party Android 16 packages without OEM system signing.
