## 2. Key Security Findings & Verifications

### 2.1. API Key & Credential Isolation
- **Rule:** Third-party credentials (such as `GEMINI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `VAPID_PRIVATE_KEY`) must never be bundled into the client build or prefixed with `NEXT_PUBLIC_`.
- **Audit Result:** PASS.
  - `GEMINI_API_KEY` is loaded exclusively on the server in `apps/api/src/modules/ai/ai.service.ts`.
  - Client components communicate exclusively with `@assistant/api` routes (`/api/v1/ai/chat`, `/api/v1/ai/briefing`).
  - No secrets exist in `apps/web/src` bundles.

### 2.2. Multi-Tenant User Data Isolation
- **Rule:** Every database query must strictly enforce `where: { userId }` scoping to prevent cross-account data leakage.
- **Audit Result:** PASS.
  - AI tools (`getPersonalBriefing`, `getFocusSummary`, `getGoalsSummary`, `getFinanceSummary`, `getDaySchedule`, `searchKnowledge`) explicitly bind `where: { userId }` to all Prisma model calls.
  - Action proposals enforce `userId` identity verification prior to execution.

### 2.3. Consequential Action Authorization Gates
- **Rule:** High-impact operations (deleting data, creating financial transactions, modifying schedules) must require explicit secondary human confirmation.
- **Audit Result:** PASS.
  - Actions generated by AI follow a two-step state machine: `PROPOSED` -> `EXECUTED` (or `REJECTED`).
  - The frontend renders explicit `Confirm` and `Cancel` controls. The API requires a separate `POST /api/v1/ai/actions/:id/execute` invocation with valid user credentials before executing the underlying business logic.

### 2.4. Financial Privacy & Voice Announcements
- **Rule:** Audio synthesis must not broadcast private financial numbers in shared environments.
- **Audit Result:** PASS.
  - Financial voice announcements are disabled by default.
  - When enabled, exact monetary amounts are masked in the audio utterance, vocalizing category status rather than dollar values.
  - A privacy toggle (`Eye` / `EyeOff`) is provided on the dashboard and AI context drawer.

### 2.5. Autoplay & Microphone Permission Boundaries
- **Rule:** Web applications must adhere to browser security models regarding media capture and playback.
- **Audit Result:** PASS.
  - Microphone access requests explicit browser permission (`navigator.mediaDevices.getUserMedia`).
  - Background audio synthesis is constrained to user gestures in compliance with WebKit and Chromium autoplay policies.
