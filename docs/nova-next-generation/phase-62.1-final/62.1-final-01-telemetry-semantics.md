## 1. Distinct Timestamp Definitions

To eliminate any ambiguity between device presence and notification synchronization success, the following semantic rules are enforced:

| Field | Subsystem Owner | Exact Meaning | Updated When |
| :--- | :--- | :--- | :--- |
| **`lastSeenAt`** | `MobileService.recordHeartbeat()` | Last authenticated device telemetry ping or heartbeat | When `DeviceHeartbeatWorker` sends heartbeat (15m periodic / startup) |
| **`lastSuccessfulSyncAt`** | `MobileService.ingestEvent()` | Last successfully accepted batch notification event | When `NotificationSyncWorker` successfully posts event to `/api/v1/mobile/events` |
| **`lastSyncErrorAt`** | `NotificationSyncWorker.kt` | Timestamp of last failed sync attempt | When network/HTTP error occurs during event batch post |
| **`lastSyncError`** | `NotificationSyncWorker.kt` | Sanitized error code (e.g., `HTTP_429`, `NETWORK_TIMEOUT`) | Preserved in device diagnostics for troubleshooting |

Heartbeat acknowledgment strictly confirms device connectivity and telemetry state; it does **not** mark pending Room notification events as synced.
