## 1. Freshness Threshold Evaluation

The backend `NotificationCapabilityService` enforces tiered freshness thresholds against `device.lastSeenAt`:

1. **Active / Fresh (`< 2 hours`):** Device is considered connected. If permissions are granted, capability evaluates to `FULLY_CONNECTED`.
2. **Delayed / Standby (`2 hours to 48 hours`):** If no events were recently ingested, listener state marks as `LISTENER_DISCONNECTED` (Standby mode).
3. **Stale / Sync Failing (`> 48 hours`):** Capability transitions to `SYNC_FAILING`. AI directive guides user to check Android battery optimization and launch the companion.
4. **Revoked Device:** Marked as `REVOKED` in database. All API requests (heartbeat, event ingestion) return HTTP 401 Unauthorized immediately.
