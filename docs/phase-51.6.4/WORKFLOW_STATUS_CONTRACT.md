# Phase 51.6.4 — Canonical Workflow State Contract

## 1. Domain Model Differentiation

Nova maintains a clear separation between the workflow plan lifecycle and individual action/idempotency execution records.

### A. Workflow Plan Lifecycle (`WorkflowPlan.status` / `WorkflowStateMachine`)
Defines the state of the multi-step DAG orchestration:
- `DRAFT`: Initial decomposed proposal generated by AI planner.
- `PROPOSED`: Presented to the user awaiting explicit authorization.
- `CONFIRMED`: User approved; queued for worker execution.
- `RUNNING`: Worker lease acquired; executing DAG steps in topological order.
- `COMPLETED`: All steps executed successfully.
- `PARTIALLY_COMPLETED`: Some non-critical optional steps completed, but plan finished.
- `FAILED`: An unrecoverable step failed; saga compensation invoked.
- `COMPENSATING`: Reversal/undo actions currently in flight.
- `COMPENSATED`: All executed compensations completed cleanly.
- `CANCELLED`: Explicitly cancelled by user or operator prior to or during execution.
- `REJECTED`: User rejected proposal.

### B. Action & Idempotency Record (`AIAction.status`)
Defines the durable PostgreSQL state of an atomic action or step idempotency slot:
- `PENDING`: Atomically claimed by a worker; lease active for up to 15 seconds.
- `EXECUTED`: Domain mutation committed successfully; payload stores immutable result.
- `FAILED`: Execution terminated with error; slot unlocked for recovery.
- `CANCELLED`: Action cancelled.
- `COMPENSATED`: Action reversed via compensating tool.

## 2. State Mapping & Contract Matrix

| WorkflowPlan State | AIAction State | SSE Event Emitted | Frontend Proposal State | Terminal? |
| :--- | :--- | :--- | :--- | :--- |
| `PROPOSED` | `PROPOSED` | `plan_proposed` | `PROPOSED` | No |

| `COMPENSATED` | `COMPENSATED` | `plan_compensated`| `COMPENSATED` | **Yes (Immutable)** |

## 3. Concurrency Protection & Terminal CAS Update
Terminal states are immutable. In `WorkflowOrchestratorService` and `AIAction`:
```sql
UPDATE "AIAction"
SET status = 'EXECUTED', payload = :payload
WHERE id = :id AND status IN ('RUNNING', 'CONFIRMED');
```
If a workflow is concurrently cancelled, the conditional update count is `0`. The worker immediately halts without overwriting the user's cancellation. Verified via `scripts/test-state-concurrency.js` (6/6 scenarios passed).
