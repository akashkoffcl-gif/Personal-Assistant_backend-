# 63.1-02 — Wake-Word Implementation Technical Inspection

**Project:** NOVA Personal AI Companion  
**Phase:** 63.1 — Native Voice Evidence Closure & Certification Audit  
**Auditor:** Principal Android Architect, Android Audio Systems Engineer  
**Source File:** `apps-mobile/nova-android/app/src/main/java/com/nova/companion/voice/WakeWordEngine.kt`  

---

### 1. Architectural & Algorithmic Classification
Inspection of `WakeWordEngine.kt` reveals the exact mechanism:
- **Underlying Engine:** Standard Android platform `android.speech.SpeechRecognizer` using `RecognizerIntent.ACTION_RECOGNIZE_SPEECH`.
- **Acoustic / ML Model:** Neither a dedicated on-device acoustic keyword spotting model (e.g. Porcupine, Snowboy, or TFLite Micro acoustic model) nor a custom phoneme classifier is embedded in the binary.
- **Audio Processing Topology:**
  - Microphone audio buffers are captured by the system speech recognizer provider (`com.google.android.googlequicksearchbox` or OEM voice recognizer).
  - The engine relies on the platform `SpeechRecognizer` to emit partial and final candidate transcripts via `RecognitionListener.onPartialResults()` and `RecognitionListener.onResults()`.
  - Detection occurs via in-memory string matching against `listOf("hey nova", "nova", "jarvis")`.

---

### 2. Network Requirement & Local Processing Reality
- **Network Dependency:**
  - Android's `SpeechRecognizer` may process speech on-device if offline speech recognition packs are installed (e.g., Google Speech Services offline language pack); otherwise, audio feature frames are dispatched to Google/OEM recognition servers.
  - Therefore, `WakeWordEngine` cannot be truthfully characterized as a standalone, guaranteed offline acoustic DSP detector.
- **Battery & Low-Power Constraints:**
  - Running continuous `SpeechRecognizer` sessions consumes standard microphone audio streams and CPU cycles. It does NOT utilize low-power always-on hardware DSP audio buffers.
  - On Vivo/iQOO devices (OriginOS / FuntouchOS), low-power DSP hotword listening is restricted by system security architecture to the privileged OEM assistant (`com.vivo.assistant`).

---

### 3. Truthful Terminology Standard
In accordance with NOVA architectural directives:
- This implementation is classified as **"Active Software Keyword Spotter via SpeechRecognizer"**.
- It is **NOT** a "Dedicated Hardware DSP Always-On Hotword Engine".
- Any previous marketing or theoretical claim of zero-battery DSP wake-word is officially rejected by this audit.
